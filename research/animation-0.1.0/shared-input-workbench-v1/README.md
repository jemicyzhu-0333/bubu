# Shared D2 input workbench v1

One actual admitted actor combines the frozen r4 continuous light drag loop, petting, pointer capture and D2 N3 cavity tint. `workbench.html` explicitly uses `createD2PointerHost`. `createPointerHost({modelVariant:"full18", ...})` retains original gold full18; `modelVariant:"d2"` or the named D2 entry selects both the strict prepared pack and matching policy. Unknown variants and crossed asset/profile pairs reject without fallback.

The browser entry takes a bounded pack reader, real target and camera. It does not take a caller-owned actor, face driver, eligibility claim or body writer. The single canonical P1 owns one canonical Director/Timeline and writes morph plus D2 style through the same actor apply. BodyRigAdapter owns only four permitted bone quaternion channels and host wrapper transforms. Historical prototypes remain archival dependencies for their pure controllers/adapter; their vendored runtimes are not imported.

Default artistic policy remains empty outside this explicit test fixture. `.82` seconds r4 cycle and 10-degree workbench yaw are prototype values, not newly approved product timing. N3 uses the existing D2 actual-amount style gate; other expressions/Basis are zero. Pointer pickup exercises N3 on the same model as body motion.

## Run

Restore repository sibling layout; install the pinned Three dependency in runtime-facepath05 and this directory with `npm ci` when registry access is available. Run `npm test` here, in runtime-facepath05, and in expression-scheduler-p1. Serve the animation directory using an approved local preview route and open this workbench. No server/security bypass is supplied.

Tests use actual GLBs, real skin raycasting and fake DOM/scheduler. Browser/OS pointer behavior, actual GLSL compilation/WebGL rendering and user visual acceptance remain unverified.

## Lifecycle

Complete event timestamps are batched before advance. Hidden/blur invalidates capture, queue and interaction epoch; stale input cannot reacquire ownership. Dispose is idempotent. Admission/body construction, subsequent initialization, listener registration and initial RAF request failures clean all acquired resources. Frame/RAF failures stop the host; cleanup attempts every listener/controller/body/owner/pool even if a cancellation cleanup throws.
