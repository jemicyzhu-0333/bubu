# bubu 0.1.0 表情时序与选择策略提案

状态：设计草案，尚未接入或获艺术验收。2026-10-17。
基线：`bubu-runtime-0.1.0-facepath06-20261017`。本提案没有改动其源码、测试、manifest、静态脸、八层绑定或既有渲染任务。所有节奏参数和情绪映射都须另外确认。

## 1. 建议结论

用户提出“间隔不一定一样，可能有不同权重”是有用的设计方向，但应拆成两个独立问题：

- 时间设计：什么时候出现、多久到达、到达后留多久、退回多久、两次自主表现之间等多久。
- 选择设计：符合当前情境的候选表情中，哪个更容易被选中。

权重高不代表停得久；停得久也不代表更常出现。应分别记录“选择次数占比”和“可见停留时间占比”，避免误判调参效果。

建议先做“显式交互脚本 + 情境加权待机调度”的上层策略，不将随机逻辑塞入FaceTimeline或morph绑定。不混合不同语义的几张脸。艺术路径内部时间曲线作为独立第二阶段，不能借“权重”修改形状路径。

## 2. 四种互不混用的量

| 量 | 建议字段 | 精确定义 |
|---|---|---|
| 选择权重 | `selectionWeight` | 一次决策中合格候选的相对机会；0表示不可随机选中，不是淡出强度 |
| 路径进度 | `amount` | 当前单一批准路径上的0..1强度坐标；映射八个艺术knots |
| 时间参数 | `enterSec / exitSec / holdSec / gapSec` | 进入、退出、可读停留、退出完毕后的自主空档 |
| 再次资格 | `cooldownSec / excludeRecent` | 候选离开后多久可再选，以及最近选中过哪些候选 |

艺术knots目前固定在0.125、0.25…1，是空间/形状进度位置，不是等时帧。FaceTimeline的smoothstep使经过这些位置的实际时间本来就不均匀，但无法指定任意逐段时长。修改选择权重绝不应影响knots位置或morph权重。

## 3. 建议配置分层

新增独立、版本化、严格校验的sidecar `bubu-expression-policy`；当前face manifest严格拒绝新字段，第一阶段不要往里面追加policy或修改profile。sidecar绑定已批准pack及profile摘要，未来若纳入pack，须单独版本升级、哈希锁定和admission测试。

建议字段表（这是接口提案，尚不是引擎可执行JSON）：

- 顶层：`format`, `version`, `packDigest`, `profileDigest`, `rng`, `limits`, `candidates`, `contexts`, `sequences`, `reducedMotion`。
- `rng`：算法版本、非零32位seed；可回放运行记录另含事件序号、决策序号和随机计数器。
- candidate：唯一`key`、批准`faceId`、`amount`、`selectionWeight`、`enterSec`、`exitSec`、`hold`、`cooldownSec`、`when`。
- `hold`：显式`fixed(sec)`或`uniform(minSec,maxSec)`的判别联合。第一阶段不支持任意分布、函数或无限区间；没有隐含默认值。
- context：唯一`key`、显式candidate key列表、`gap`、`excludeRecent`、固定策略`onEmpty: stay-current-and-wait`。gap同样用fixed/uniform联合。
- sequence：由真实事件触发的明确step列表，每步引用candidate或明确的face目标；step停留从实际到达起算。明确结束行为和释放/取消入口，不让任意配置字符串决定事件优先级。
- `when`：有限枚举事实的声明式条件，例如当前宿主模式、是否存在真实交互所有者、motion preference；禁止eval、任意脚本、URL、设备信息推断和未批准情绪推断。

具体脸ID到交互/情境的映射由艺术与交互审批提供。不能根据名称、候选权重或本提案替用户决定“开心/生气”等语义。

### 时间边界

1. `hold`从该意图的`actualArrival`开始，不能从请求时间或预估进入结束算起。
2. `gap`从前一自主表现真正退出至Basis开始；gap期间不应仍显示待退出的脸。若设计要求留在某个待机脸，该意图应显式配置，不能把Basis和R0混作一回事。
3. 自主选择的`cooldown`从候选失去可见路径所有权开始；中途被打断也进入冷却。仅预选但未发出，不消耗冷却。预选后立即被抢占而未显示的情况需记录为未展示，不计曝光。
4. 防重复针对candidate key与faceId双重检查，防止同一脸用不同配置key绕过。
5. 空候选时不放宽条件、不强行重复：保留当前合法状态；等待最早冷却期限或条件变化。若当前状态必须结束，按显式退出策略回Basis后等待。
6. 同脸同amount重复cue在当前引擎里幂等，不会重启hold。高层需要明确`keep-hold`或`restart-logical-hold`语义；后者只改变策略计时：已到达时从新请求时刻起算，移动中仍等待当前token对应的真正到达；不得复用旧actualArrival生成已过期期限。每次新请求有独立token，匹配目标与阶段后才能接受arrival。

## 4. 决策与可回放

- 只在gap结束、冷却资格恢复且需选择、情境改变、真实事件开始/结束等决策点进行筛选。每帧不重抽、不扫描候选、不创建候选数组。
- 从稳定顺序的候选中剔除条件不符、冷却未满、最近重复、weight=0项；对剩余权重做一次累计加权抽样，复杂度O(候选数)。不做“抽到不合格就重抽”。
- 建议v1权重采用有界非负整数，累计总和为安全整数且限定在32位范围；零总和视为空候选。用版本化32位PRNG和无偏有界取样；拒绝抽样的额外抽取也须计入日志。固定顺序、算法版本、溢出规则都应成为协议。
- 选择、hold与gap使用独立确定性随机流，仅隔离各类随机数消耗；改变hold会改变未来决策时刻与候选资格，因此不保证未来脸序列不变。固定参数不消耗该流；仅在该次动作被接受时采样一次并保存。
- replay输入至少包含：policy与asset摘要、PRNG版本/seed、初始状态、按时间及序号排序的真实事件/条件变化、可见性/暂停事件。日志包含：过滤原因、总权重、选中候选、抽样时长、请求时间、实际到达/退出时间、抢占原因。
- 同一事件历史应在30/60/120Hz和大时间跳跃下得到相同决策。高层按规范时间处理到期点，不能以RAF实际唤醒时刻重算节奏。
- 页面隐藏若暂停，actor与director必须共用同一明确逻辑时钟映射（wall减累计暂停），不能只冻结策略而让actor沿wall clock推进。隐藏/恢复事件与时间映射进入replay。P0不实现visibility宿主接入；不得暗中跳过已排事件或补演规则。

## 5. 真实事件、抢占和长按

高层拥有唯一face writer。建议固化优先顺序：显式取消/释放或宿主失效处理 > 当前真实交互事件 > 自主待机。具体事件类型和语义需交互方案批准；candidate配置不能自行提高优先级。

- 事件在同一规范时间由宿主收齐并一次提交batch；先采样actor到该刻，再以真实事件仲裁，使旧token/generation失效，最后判断仍有效的内部期限，仅提交胜出的cue。已advance封闭的时间不接受迟到同刻事件。晚到的旧hold、冷却回调和预选结果不得复活旧意图。
- 不预先把整段低优先级待机cue塞入FaceTimeline。未来脚本step保存在高层，只在其规范到期点提交；真实事件到来时可丢弃尚未提交的低优先级step，不需要强迫退回Basis来清队列。
- 注意当前引擎cancel会清空全部已排队事件，并且压过同一时间戳所有face。禁止通过“cancel(t)+face(t)”抢占；全局取消本身就是该时刻的最终决定。owner release只释放匹配owner+requestId+lifetime。lifetime为每Director全局严格递增safe integer，整批原子验证，reset不回退已用水位；仅保存一个高水位值，不用无界Set。requestId标签可以重用，旧lifetime释放仍无效；使用普通安全退场，不能清空新owner或未来真实输入。之后的新事件必须按真实、更晚的规范时间进入，不能偷偷加epsilon绕过取消。
- 普通交互替换只发新的face意图，使用当前同脸安全反转/跨脸Basis路径；释放必须能及时改变意图，不等待表情hold或脚本完整演完。
- 长按阶段可设计为“明确进入 → 稳定保持 → 真实释放后退出”；如需持续变化，使用有冷却的稀疏机会点和最大自主变化预算。不可机械重复固定循环，也不可随机表情抢占仍有效的真实事件。长按时长本身不推导新情绪。
- 当前包无指针、拖拽、长按API，本节是未来宿主策略要求，不宣称这些已支持。

## 6. 减少动态与性能

- `reducedMotion`应关闭自主循环/随机切换，优先保留稳定脸；必要真实反馈使用明确、已审查的简化路径和既有安全过渡。不要简单把fade改成0：目前合法范围为0.04..2秒，而且立即跳变破坏当前连续性承诺。
- motion preference改变是规范事件；使旧generation失效并重新仲裁。是否退Basis、保留当前脸或换稳定脸需明示设计，不能由配置缺省猜测。
- 新高层runtime wrapper提供`advance`, `isAnimating`, `nextDeadline`，最早deadline需合并：timeline队列、预估到达边界、实际hold到期、退出完成、gap、必要冷却边界。稳定hold不触发RAF；没有工作时deadline为Infinity。
- 现`FaceTimeline.nextDeadline()`仅返回队列首事件，过渡终点由RAF推进；上层需利用`arrivalTime`在推进到边界后确认`actualArrival`，防止大时间跳跃吞掉完整hold。
- 上层事件处理预算/候选数/历史长度/脚本步数必须有显式上限。大时间跳跃的成本与实际处理决策数有关，不是恒定O(n)。预算耗尽须保留目标时间、未处理事件和已推进位置，分批继续；不丢事件、不提前声称到达目标，也不改用RAF时刻重算期限。
- 概率调度只触碰语义cue，不扫描scene、顶点或morph targets。不会减少当前八层绑定写入或GPU自身成本，也不宣称已证明渲染性能。

## 7. 第二阶段：艺术路径内部非均匀时序

`pathTimeMap`必须与selectionWeight分开。建议未来限定为一个批准faceId上、时间严格递增的`(elapsedSec, amount)`关键点。重复amount表示真实停留，单次进入/退出方向单调，范围0..1；禁止跨语义ID、越界、任意morph数组、任意插值脚本。

可以先用现有同ID不同amount cue做机械原型：每段smoothstep到达后停留，再发下一段。但每一段都停速，并可能在被打断时刹车；这不等同于连续通过各knots的艺术时间重映射，也不能宣称自动具有自然观感。

连续time-map需要单独能力版本、插值/导数与中断政策、实际到达预测及帧率不变测试；不能直接把强度作为任意函数塞入adapter绕开FaceTimeline。无论如何仍保持单一语义路径，跨脸经Basis，同脸反转沿当前批准路径。

## 8. 校验和接入门槛

JSON Schema做结构校验，再做语义校验；配置读入一次、深冻结后再编译。

- 所有对象拒绝未知字段；数值有限且有界；ID唯一、引用存在；range满足min≤max；正时间下限防止零时长决策死循环。默认值必须在文档列明，建议v1要求显式提供。
- JSON文本不可能含NaN，但程序式入口仍须拒绝NaN/Infinity/accessor/prototype/symbol，与现cue严格度一致。
- 哈希/pack/profile能力匹配；仅批准七槽；未批准路径、额外脸、原始morph权重、geometry/材质变更一律拒绝。
- entry/exit必须符合既有0.04..2秒及时钟headroom。hold/gap/cooldown及集合大小的新技术上限在实现前确定；它们不是最终艺术节奏。
- 宿主真实事件优先级和能力边界不能由policy覆盖。错误配置必须拒绝装载，不静默clamp或降级。

验收新增用例：确定性回放；hold从实际arrival起算；同cue幂等；空集合/零权重；faceId别名防重复；冷却边界；取消同刻；旧generation隔离；长按释放及时；reduced-motion；可见性暂停；大跳时序；队列/事件预算；不活跃时零RAF；七槽/八层单路径逐槽不变量。视觉验收单独验证可读停留、过点节奏和长时不机械，数值测试不代替艺术审查。

推荐顺序：先确认各字段语义 → 独立policy schema与纯逻辑replay测试 → 宿主wrapper接现cue → 做短长两种可视化验证 → 最后才考虑路径time-map。现有facepath06测试和已批准静态脸作为不可改的回归基线保留。
