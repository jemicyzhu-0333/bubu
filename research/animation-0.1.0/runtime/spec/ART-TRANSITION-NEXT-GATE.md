# Next integration gate (design only; runtime expansion paused)

Neutral04 is the current stopping point. Wait for the complete reviewed basic expression library before implementing expression activation or the final two-step long-press/drag behavior. Keep the full capability roadmap; this pause does not remove missing capabilities.

## Required asset/profile facts

- One frozen source revision/hash and chart; historical r6 face05 and its replacement are different assets. Shape approval, intended semantic reading and verified runtime use remain separate fields.
- Full component roster: body, both eyes, both highlights, mouth, optional brows and tongue. Unknown components reject; every active/neutral path explicitly sets or hides every component. Body remains shared with no per-expression geometry copies.
- Distinguish original Basis, a short-horizontal neutral design such as R0, and expression intensity0. Do not silently replace the approved original rest or map all three to one ID.
- Preserve the authored piecewise POSITION/NORMAL paths, source COLOR/materials and exact neutral. Approved degeneracy (closed highlighter/closed-mouth inner rim/hidden brows or tongue) is explicit rather than rejected as generic bad geometry. New tongue attachment and mouth occlusion need their own checks.
- Current r6 permits a single semantic face and adjacent intensity knots, with a neutral bridge across faces. No direct two-face blend is approved. New library adjacency is a separate shape-path review; names or a simplex weight sum cannot authorize it.
- Gaze, brow movement independent of a face, mouth interiors and knee/neck anatomy are unsupported until real bounded channels and bindings exist. Highlights are not gaze controls.

## Transition contract to review before implementation

- Cue semantics reference approved IDs and input intent, not historical controller names. Authored duration, hold, arrival and exit must be visible in the specification.
- An interrupt evaluates current shape intensity first, withdraws continuously to the verified neutral state, and only then activates another path unless that exact pair has an approved direct transition. Updated intent may replace the queued destination without resetting the current shape value.
- Body/action cues share the same event clock but preserve authored timing. Expression arrival should define a readable hold; do not count a bridge as a full-intensity hold or lock mouse/release to complete a face.
- Readiness distinguishes resident/prewarmed assets from pending decoding. A neutral bank switch would be atomic only at exact neutral. Any residency policy must compare full-library residency against pinned common variants and candidate preloading with actual GPU evidence; no per-frame geometry mutation or body duplication.
- Tests will cover every knot and intermediate path, missing roster, wrong hash/semantic binding, early cancel/regrab, bridge interruption, zero recovery and multi-angle99px readability. Existing neutral CPU parity is necessary but does not pass this gate.

Mouse latency, expression transitions, final interaction and native/Electron require later distinct scenarios.
