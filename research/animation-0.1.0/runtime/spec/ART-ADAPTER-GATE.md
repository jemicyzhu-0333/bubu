# Art adapter gate — not an active profile

This document is not a loadable runtime pack. The first slice deliberately accepts only `purpose: mechanics-fixture`.

The approved 05 shape and r4 rig are reference evidence. r6's selected shapes 01/04/05/07/08 have a historical approval record; expression 05 has since been reopened and is currently revision_pending. The other selected shapes remain reference evidence; this does not approve the unfinished complete expression library or activate an interaction. A shape ID, its semantic reading, and its verified runtime use are three distinct facts. In particular, 01 must not be automatically treated as `surprise` because an older controller used that name; its current dominant reading is curiosity and semantic use needs review.

A future face adapter must preserve the fixed body-local coordinate chart, include both eyes/highlights/mouth, map approved per-path intensity curves and prove exact neutral. Eye shape, eye orientation/gaze and highlight attachment should be separate declared layers. An absent layer remains unsupported; a highlight must never silently stand in for a pupil. New brows need a separate bounded layer and explicit ownership.

Direct r6 cross-face overlap is forbidden. The fixture's single-path machinery does not certify r6's geometry, represent all 20 candidate expressions, or approve any proposed timing. The original mechanical loader keeps its strict restrictions. A separate checkpoint04 loader supports the fixed r6 neutral source, including NORMAL morph data. Expression activation still requires the complete basic expression library to be approved and archived, followed by new sampled-shape, multiview and event-time checks.

Latest art status: a separate short-horizontal neutral variant and new bounded brow/inner-mouth layers are candidates only. Archived Basis is unchanged. Candidate files do not authorize a new binding; independent gaze remains unimplemented.

New artistic candidates can use sparse morph accessors with no base bufferView. The mechanical loader intentionally rejects them. The neutral art parser now validates bounded sparse decoding, indices, ranges and decoded work explicitly in synthetic tests; raising morph-target counts alone is insufficient. Actual new candidate hashes remain unregistered. No candidate sparse data is activated in this checkpoint.

Checkpoint04 adds one explicitly limited adapter: hash-locked static05 and historical r6 neutral rest loading. It preserves full source geometry/material/morph data but holds every morph weight at0 and exposes no expression/motion activation API. Shape-source history, intended expression semantics and runtime interaction approval remain distinct. The historical r6 face05 endpoint is not the current artistic direction. New brows, tongue layers, gaze and the growing basic face roster require a new full binding/mapping gate and cannot enter through this adapter. See NEUTRAL04.md.
