# Portable final-candidate check

Run from this directory (Three.js dependencies must already be installed):

```sh
npm test -- --repo-root /path/to/repository --reference-root /path/to/verified-fixture --cache-root /path/to/generated-cache
```

The fixture must contain the verified fixture-source-manifest.json, original D2 source and hybrid GLB/binding manifest. The cache must contain accessory/review/halo-static.json generated by the fixture preparation pipeline. All generated models, original-hand extraction, mounts, fresh reports and current-evidence.json stay under the cache. No upstream recovery checkout, old reports, or sibling workspace is read by this check. Historical reports and historical hashes remain provenance, not current acceptance.

The check regenerates model GLBs and compares bytes against the shipped candidates, generates actual mounted meshes, recomputes static audits, then hashes inputs/outputs and verifies the evidence. To verify the existing current evidence again:

```sh
python ../shared/verify-work-garden.py --proof /path/to/generated-cache/work-props/reports/current-evidence.json
```

Work mounts replay the fixed matrices and translations in src/final-hand-transforms.json selected by the historical cap-fit run. No optimizer is run; unchanged source hands are freshly extracted from the hybrid reference GLB. Garden mounts use shovel/broom depth-v2 and watering-can fixed-stage-v2; the older initial placements are only intermediate regeneration inputs. Original model geometry and final fit parameters are unchanged.

Dependencies: Python 3, Blender with mathutils BVH, Node.js and Three.js 0.186.1. Static evidence does not establish user visual approval, garment/action compatibility, or native-runtime acceptance. Historical finalize/report-board utilities are archival authoring tools, not acceptance entry points; do not run them to replace provenance reports.
