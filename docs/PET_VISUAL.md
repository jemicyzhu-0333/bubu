## 状态组合初版冻结

六格获认可设计关系图保存在各形态 `real-events/sources/state-combinations-v1/`，含原稿哈希与提示词；只用于佩戴/遮挡关系，不替换canonical身体。
音乐+AI复用一台朝向宠物的电脑、耳机和侧边机器人。专注使用原会话动作的单一手持工具，附加配件不重写手、脸、身体或脚部轨迹。
后带藏在头/耳/帽后，耳罩留在五官外，机器人与衣料留空；左右镜像、裸装与代表性完整重穿搭、六种专注动作的故事阶段都要检查；这不等于穷尽全部衣柜组合。
初版穿搭在此冻结；后续只针对已证实缺陷修复，不扩展服饰与美术范围。

## 语境辨识强化

音乐以更清楚的软垫耳罩、深色外壳/内垫分界和侧支架辨识，不能靠扩大到眼睛区域或把帽子摘掉。
AI 的小机器人位于身体侧下方，约27 CSS px 宽；奶油/薄荷/淡紫配色、少量面屏五官与空白便笺表达伙伴身份，
只做假装一起整理思路的小动作，不显示任务内容或真实生成进度。团子使用生成 PNG 道具层，乌萨奇使用原生矢量层，
两者都不替换获认可的身体、双波嘴/小五官、短手、两脚或衣物。团子在最重穿搭下将机器人起点定于x78美术单位，
保留披风与便笺之间的空隙；机器人不会为了露出全部部件而盖过衣物。

下方context图标和contextual短句交替占用舞台内固定区域，说明文字仅按需展开或悬停；短句使用12px系统文字，不把字烤进角色素材。
会话星轨沿用120×26脚下区域；底部184px处为200px宽单行，72px状态／动作、90pxcontext、26px喂食，两个6px间距。
idle不显示会话文字，状态以SVG图标和颜色区分，完整名称与时间可访问；两种形态、身体canvas、命中框与原生anchor均不改变。
共有状态规则见 ARCHITECTURE「活动镜像」。所有新道具随同一生命周期退出，不能留下单独的机器人、手或标签。
低刺激/减少动效固定完整伙伴与标识，不循环讲话。原生99 CSS px身体宽度、2×、左右/三分之四、浅深背景和代表衣柜均须检查。
团子参考/生产原稿/拆分配方在 `raster/sources/tools/context-emphasis-v2/`，乌萨奇关系图在 `usagi/real-events/sources/context-emphasis-v2/`。
实际 DOM/CSS 浏览器验收、按声明尺寸画出的 Canvas 文字布局代理和角色 Canvas 渲染必须明确区分。

## 1. 舞台与坐标契约

几何由 `src/core/pet-stage.mjs` 独占，renderer 与美术模块都不得再出现散落的画布字面量。

```text
身体美术坐标 66×66 → 四周40单位余量 → 舞台146×146
  → CSS219×219；两种当前形态按实际 CSS×DPR 建光栅
  → 命中框和原生窗口契约保持；路径、材质和纹理不再压成33×33格
```

尺寸证据必须区分身体设计宽度、画布尺寸与实际非透明前景高度。66 美术单位按 1.5 CSS px/单位显示时，
身体设计宽度是 99 CSS px；两倍图是 198 CSS px。乌沙奇的长耳与衣物会伸出该身体框，
完整前景可高约 144–145 px，不能把这类运行时截图标成“整只角色高 99 px”。
若要求完整前景恰为 99/198 px 高，须另按 alpha 包围盒量测并输出相应缩放证据，标明它与原运行时尺寸的区别。

`dango` 和 `usagi` 共用闭合的 artist 合成协议，但素材来源不同。当前团子兽默认由
`dango-raster-production.mjs` 读取 `assets/companion/dango/raster/dango.raster.mjs`，绘制生成 PNG 的身体、
独立耳脚、五官、工具与衣物；保留获确认原图的圆身、短耳、小五官、适度阶梯轮廓和十套皮肤身份。
乌沙奇的 canonical 身体/脸仍来自 SVG 编译的 Rig，生成 PNG 只用于已登记衣柜与场景素材。
桌宠和伙伴页使用实际 CSS×DPR 光栅、对应素材的平滑策略和连续姿势，不能用通过离屏检查推断真实 Windows 缩放验收已完成。

团子兽 `dango.vector.svg`、`dango.appearance.vector.svg`、`tools/dango.tools.svg` 与原矢量画笔继续保留，
供回退开发和同尺寸对照，不是当前默认分派；加载中的同源 neutral PNG 回退也不等于自动切回矢量画笔。
旧 33 格资产只用于历史对照与编译回归。v3 参考属于历史矢量阶段，当前生图形象基准与来源身份见文末生产流程，
任何设计参考都不能冒充实际运行截图。

## 2. 配饰分层与五条不变式

配饰分两层合成：`back` 在身体之前，`front` 在身体与脸之后。一件配饰可以在两层留下部件。
内容目录仍是 `src/content/appearance.mjs`；团子兽由 `dango-raster-appearance.mjs` 按 PNG 描述绘制，
乌沙奇由 `usagi-art.mjs` 装配生成衣柜与经典路径款。活动手脚最后按同一姿势盖回，不能把手脚烤死进新衣料。
历史矢量原稿/画笔和 `test/dango-vector-wardrobe.test.js` 继续维护，但不能替代当前生成层的检查。

1. **前景层不许进入五官区。** 按每个朝向的实际眼嘴与完整表情检查；服饰不能遮住张嘴下沿，也不能用改身体来避让
2. **背层衣物必须有可见体积。** 披风、背鳍与膜翼在身体轮廓外保留可读部分，后层不能只是完全遮住的漂亮单品
3. **帽、耳与手保持真实遮挡。** 先按穿戴图确定前后层，再绑定挂点；不把正面缩窄当侧转，不通过服饰重画耳朵或脸
4. **帽类与光环要为动作留余量。** 当前 PNG 描述的升降与弧线布局以同尺寸合成、跳跃/打嗝峰值及分数 DPR 检查为准；
   历史矢量的 `HEAD_LIFT = 14.5` 和路径笔触范围只约束旧实现，不能直接成为新素材的 fit 依据
5. **配饰必须满足既有舞台安全区。** 描述中的 `rect`、骨骼和 bleed 与实际透明像素一致；动作后的边界另行采样，
   不扩大舞台、命中框或窗口来隐藏越界

### 配色规则

配饰颜色不从皮肤调色板取。皮肤自带配饰曾经与本体同色（金冠配金身、蓝鳍配蓝身、绿叶配绿身），
等于没有配饰。每件都按“与宿主皮肤拉开明度或色相”单独定色；生成配饰保留获确认参考的线宽、有效像素尺度、
光源与细节密度，不能借更密的织纹、缝线或高光抢走身体和脸的识别度。

### 下半身的空间分配

历史矢量的 y∈[43,64] 下半身带曾同时容纳围巾、挎包、鞋子和披风侧摆；当前生成版仍按真实嘴区与脚底测量。
任何横跨整条腰线的硬直彩色宽带都会读成
“腰带”而不是“围在颈上”，所以分配规则是：

- 围领沿圆身做柔软弧线：浅薄荷与淡紫毛线交错，实际短针脚和细曲线表达编织，左侧短巾尾向外垂下；整圈保持在嘴区以下；
- 鞋子贴住两只脚的真实位置，鞋底不向外出檐，保住中间透明脚缝；
- 挎包与披风把主要体量压到轮廓之外的 bleed 里，只在边缘露出轮廓识别点。

## 3. 手部与动作

以下记录历史 33 格动作画笔的规则与缺陷修正，不是当前团子兽的生产模块说明。当前 PNG 运行时共用手与工具
接触矩阵，入口为 `dango-raster-actions.mjs` / `dango-raster-pose.mjs`；乌沙奇使用 PET_RIG 的活动骨骼。

动作层由肩—肘—手路径驱动可复用的像素手掌；掌端统一使用和脚部相同的阶梯式圆弧轮廓，不显式绘制
手指或拇指。手掌只随动作改变位置和姿态，不新增随机数、DOM 或状态写入。

手臂的层归属按**手掌落点**决定，不按左右：手掌横过躯干（x∈[6,60]）时手臂进前景层，否则留背层。
旧逻辑“左臂恒定背层”会让打鼓、看书、打字、织毛线这类内收动作只剩一只手 —— 左手掌被身体贴图整块盖住。

每个动作声明一个**连续手势循环**（`pet-anatomy-art.mjs` 的 `armPoses` 按 `progress` 计算肩—肘—手），
而不是定格在一个姿态：看书周期性翻页、打字左右手交替敲键、打鼓/影子拳击左右交替、跳舞双臂反相摆动。
摆动量不取整，交给画笔按整数像素落点，动作在相邻帧之间才连续；旧版手臂全程不变，才“卡卡的”。

需要**举着道具**的动作（望远镜、双筒望远镜…）必须在 `armPoses` 里声明托住道具的手臂，否则道具会贴在
脸上没有手扶：`look` 曾漏掉分支，双筒望远镜于是读成“糊在脸上的蓝眼镜”。道具若与手掌位置耦合
（如拳套套在拳头上），在转身视图里必须与手臂做**同一套坐标变换**，否则道具会与手脱节。

每个动作还声明一个语义 `effect`（hearts/notes/leaves/sparkles…），由 `pet-effect-visuals.mjs` 映射到
覆盖层的一支画笔。未登记的 effect 一律不发粒子；曾经缺表导致 11 种 effect 全部退化成同一个金色 ✦，
看起来“每个动作都在冒同样的十字星”。安静动作（打坐、困倦、热气）走稀疏发射器，不与庆祝类同频。

历史团子兽桌宠、表达画廊和 `tools/pet-frames/` 共用原像素动作绘制层；这些历史输出不能证明当前 PNG 或
乌沙奇 Rig 形态正确。当前证据必须使用生产 form artist 与 pet renderer（见第 7 节）。

## 4. 朝向与四视图

本节下列网格数据、单眼 profile 与旧动作分配是历史 33 格实现的可复验记录，不是当前团子兽的允许视角。
当前团子兽最大侧转为双眼三分之四；生产 `profile` 是该朝向的兼容名，独立左右斜面只在已保存素材和支持的路径使用。
乌沙奇独立保留正面、双眼三分之四、单眼侧面与背面，不能套用团子兽视角限制。

`src/core/pet-appearance.mjs` 按动作/状态选择 `front`、`three-quarter`、`profile`、`back`。
历史团子兽的四视图以 `assets/companion/dango/dango.body.svg` 为可编辑原稿：SVG 每单位是一格逻辑像素，
33×33 格继续对应 66×66 美术单位。`node tools/dango-build/cli.mjs` 以格心采样确定填色和轮廓，生成
`src/content/companion/dango-body.mjs`；`--check` 验证生成文件与原稿逐字节一致。构建不依赖浏览器、
DPR 或原生 Canvas，运行时仍只画整数像素格。原稿限定 M/L/H/V/Q/C/Z 路径、纯色调色板角色与挂点，
不支持的形状/变换明确报错，不能悄悄忽略。

以下坐标仅用于保留的历史编译网格回归，不是当前 PNG/Rig 的尺寸来源。四视图不能由正面压扁或镜像冒充。

- 正面关于中轴严格对称。第 12 行轮廓宽度为正面 33 格、三分之四 31 格、侧面 27 格；转身保留团子的
  体积，通过侧面阴影、耳根遮挡、眼距与口鼻位置表达方向
- 三分之四的近耳在画面左，远耳在画面右；远耳更低、更小且使用暗色。左侧腰身是宽而连贯的退后阴影面，
  朝向右侧仍为主体色。近眼保留 5 格宽，远眼按原稿挂点以整数格映射为 4 格宽，不缩放整个身体
- 真侧面面向右方，只露一只眼；口鼻前缘有一格轻微突出。尾巴贴住后侧轮廓，耳根连续连接头顶。
  后脚在后且脚底高一行，前脚更靠前、更低；两脚不是尾巴下的孤立小桩
- 背面不画脸、脊线方块、硬线或环形装饰；只由身体原稿保留底部暗面和耳背，`drawBackDetails` 不再补画
  中央脊沟。十套皮肤的调色板保持原值，共用同一组 palette-indexed 几何

### 原稿部件与挂点

每个视图显式保留 `torso`、`foot-left`、`foot-right` 图层；`PART_GRIDS` 导出三个独立像素图层，
按“左右脚 → 躯干”合成恰好得到兼容旧画笔的 `BODY_GRIDS`。腿根藏在躯干填色下，躯干轮廓在腿根处断开，
所以后续脚步动画可以移动真正的脚，而不是切走一块估算的身体。`BODY_ANCHORS` 使用美术单位：

| 视图 | 左脚挂点 / 右脚挂点 | 左肩 / 右肩 | 第 29 行可见脚段（逻辑格，闭区间） |
| --- | --- | --- | --- |
| front / back | (20,54) / (46,54) | (6,39) / (60,39) | 7–13 / 19–25 |
| three-quarter | (24,54) / (46,54) | (8,39) / (60,39) | 8–15 / 20–25 |
| profile | (28,54) / (46,54) | (14,40) / (54,40) | 10–16 / 20–26；后脚底 29，前脚底 30 |

`VIEW_LAYOUTS` 的五官挂点是 mask 左上角，使用逻辑格：正面双眼 (7,10)/(21,10)、嘴 (13,18)；
三分之四双眼 (13,10)/(23,10)、嘴 (18,18)；侧面单眼 (21,10)、嘴 (22,17)。
眼 mask 仍为 5×5，嘴为 7×4；远眼只在绘制时映射到 4 格宽。小嘴交互目标可由嘴挂点加 (3.5,1.5)
再乘 2 得到美术坐标，喝水等道具必须按该位置对齐，而不是照搬正面坐标。

### 视图分配：规则与穷举表

视图要表达的是**宠物的注意力在哪里**，不是“哪个角度好看”：

| 视图 | 何时使用 |
| --- | --- |
| `profile` | 意图是水平的：位移（行走/冲刺/滑行/太空步），或作用于身侧、地面的目标（挖土、浇花、搬东西、被墙角卡住） |
| `three-quarter` | 注意力或单侧道具指向一旁（往远处看、伸手接星、撑伞、拿麦克风表演），身体因此自然扭向那一侧 |
| `front` | 其余全部，包括**所有朝着用户的互动**（挥手、击掌、跳舞）与自处的日常举动 |

**硬约束（可机械检验）：自身绘制已经居中的动作不得用 `three-quarter`。** 转身会把五官整体
摆向朝向侧约 8.5 art px，却不会移动道具、也不压缩手臂；只有绘制本身已经偏向那一侧的动作
能吸收这个位移。度量方式：把该动作的手臂 + 道具按 front 渲染，取绘制跨度的中心，偏离身体
中线（art x 33）少于 8 px 就算“居中”。当前四个 `three-quarter` 动作的偏心均 ≥ 25 px；
被改回 `front` 的八个动作偏心均 ≤ 1 px。违反后果就是望远镜那类缺陷：中间那道桥盖在左眼上，
读作“脸上糊了一块蓝矩形”。`profile` 不受此限（它的手臂有真正的重映射，且居中道具仍落在身体上）。

完整归属（共 43 个动作 + 2 个状态驱动；这张表由 `test/pet-appearance.test.js` 逐项钉住，
新增动作必须同步）：

| 视图 | 动作 |
| --- | --- |
| `profile`（8） | `chase-butterfly` `chase-laser` `moonwalk` `paper-plane` `carry-energy` `dig-treasure` `plant-water` `stuck-corner`；以及 `state='walking'` |
| `three-quarter`（4） | `sing` `telescope` `catch-star` `umbrella-dance`；以及 `state='dragged'`（被捉起时身体确实会扭过来） |
| `front`（31） | `wave` `high-five` `dance` `stretch` `yawn` `drum-solo` `photo-pose` `shadow-box` `look-around` `workout` `hiccup` `juggle` `pit-fall` `mirror-meet` `sneeze` `bubble-blow` `meditate` `happy-hop` `spin` `tail-wiggle` `read-book` `type-keyboard` `sip-tea` `sweep` `magic-trick` `knit-scarf` `hide-box` `build-blocks` `snack-picnic` `tiny-chef` `take-note` |

几个容易反复的判断，结论写在这里避免反复：`wave` / `high-five` / `dance` 虽然绘制偏向一侧
（允许转身），但它们是**朝着用户**的互动，把身体扭开会直接摧毁这层意图；`drum-solo`、
`photo-pose`、`shadow-box`、`stretch`、`yawn` 的道具与双臂本就居中对称，转身只会造成错位而没有
任何收益；`dig-treasure` / `carry-energy` / `moonwalk` 的绘制也居中，但它们是 `profile`，不受这条
硬约束限制——因为 `profile` 会把肩点真正重映射到新轮廓。

- 侧身（profile）与背面（back）真的换了轮廓，所以动作肩点要重新映射到新轮廓；三分之四（three-quarter）
  **不对手臂做任何横向压缩**，因为第 12 行的轮廓宽度比是 31/33，肩根（art x 5–6 / 60–61）本来就压在身体
  上。曾经按 0.52 把远侧手臂压向中线，那只是为了迁就同样错误的“压扁 0.52”身体网格；网格改完后这个
  补偿反而把手臂整条拽进身体（手掌落点进入躯干跨度后被判成 front 层，读作“贴在脸颊上的色块”）；
  与手掌耦合的道具（拳套）必须与手臂用同一变换，不得单方面压缩；
- 身体尺寸不因普通动画入场而隐式变瘪；只有明确声明的呼吸、躲藏、伸展和用户按压反馈才允许改变位姿；
- `facing` 只负责左右镜像，不记录鼠标轨迹，也不进入持久化状态；
- 注视弹簧保持屏幕坐标，在合成活动脸时转换为镜像的局部坐标，左右朝向都看向光标。

四种视图共用同一绘制协议但不复制业务状态：身体、脸、动作、配饰分别按视图取对应网格、锚点和可见侧，
仍由 renderer 的单一合成顺序绘制。

以下是保留的历史矢量衣柜编译/回归入口；实际输入是可编辑 SVG，不是当前默认 PNG 生产路径，也不依赖未随公开树提供的设计参考。

## 6. 扩展性边界

当前换装系统已支持在同一团子兽 body rig 上自由组合已解锁配饰；它不等于任意宠物物种已经插件化。内容规模变大前要守住：

- 不把帽子、围巾、衣服塞进 `src/core/pet-action-art.mjs` 的动作条件分支；
- 不为每个“动作 × 皮肤 × 配饰 × 朝向”复制完整 PNG，避免维护成本乘法增长；
- 新配饰先进外观目录声明元数据，再按形态登记生成层、来源与 fit 契约；经典路径款才登记专属矢量画笔。
  团子兽使用正面、获确认的双眼斜面与背面并保留 `profile` 兼容别名；乌沙奇沿用 canonical 四视图和 Rig 骨骼。
  合成层仍然表驱动，新增一件不需要改合成器；
- 新动作声明可支持的朝向，不能支持时回退到 `three-quarter` 或 `front`。
- 新皮肤只能改变调色、签名配饰与特效，不得假装已经提供另一套身体、脸或命中几何。

推荐的长期 slot 结构：

```text
appearance projection
  ├─ back: 背包 / 披风 / 翅膀
  ├─ body: 衣服 / 围裙 / 盔甲
  ├─ neck: 围巾 / 领结
  ├─ head: 帽子 / 王冠 / 花饰 / 光环
  ├─ face: 眼镜 / 面罩 / 贴纸
  ├─ hand: 手套 / 手持物
  └─ front: 徽章 / 互动道具 / 闪光
```

自由装备通过闭合的 `appearance:equip` / `appearance:reset` 命令修改上述 companion slice，renderer 只消费冻结投影；
schema 9 的逐字节备份、幂等性与损坏拒绝测试已经覆盖这条迁移。

### 跨身体 rig 的形态适配层

0.1.6 已落地 companion-owned 的 form registry；当前团子兽 `dango` 使用 66 单位美术空间内的生成 PNG 分层画笔，
原矢量实现保留作回退参考。乌沙奇 2.0 `usagi` 保持四视图 SVG Rig 身体/脸，并叠加生成衣柜。两个 surface 只按
解析后的 form 选择合成协议，不按 `usagi` skin ID 散落特判。每个 descriptor 至少声明：

```text
form
  ├─ renderer + bodySize
  ├─ bodyGridByView
  ├─ faceRig
  ├─ anatomyRig
  ├─ appearanceAnchors + supportedSlots
  ├─ slotLabels + bubblePlacement
  ├─ artBounds + hitbox + bleed
  └─ motionMap + supportedMotions + fallback
```

`form-art.mjs` 是共享分派层：pixel form 回到原 `pet-art` / `pet-face` / `pet-action-art`；另一 form
必须在闭合 artist map 中提供 body、face、action、appearance、motion、expression 与 status 画笔。
`dango-raster-production.mjs` 装配默认团子兽；`usagi-art.mjs` 装配 canonical Rig、生成衣柜和点缀。
`usagi-support.mjs` 只组合经典服饰、状态点缀和整体动作画笔，不拥有身体或脸。
`activity-playback.mjs` 从原会话进度采样多段动作，`face-choreography.mjs` 配合动作推进眼嘴与视线，
不新建计时器或业务状态；通用表达导演仍决定输入安全态和必要反馈的优先级。
乌沙奇3/4保留两眼、侧面一眼；团子兽的最大侧转固定为双眼3/4，`profile`只是其兼容别名，不能再画单眼凸嘴侧脸。两者背面不画五官。披风和领口分别适配四个朝向，尾巴与手在前层覆盖衣物。
桌宠、伙伴页 hero、形态缩略图和换装预览复用这条边界；命中区、四边探头距离、气泡位置和光栅 DPR
也从 descriptor 推导。任务、背景、食物、XP、专注、提醒与伙伴关系仍是共用业务能力。

这不是“任意角色零代码插件”：新增不同身体仍至少要登记 form descriptor、实现专属画笔、登记 skin 与
该形态配饰内容，并补四视图/动作回退/安全区/命中/两个 surface 的行为和视觉验证。只有共享同一 rig 的
调色与内容扩展才只是目录数据。形态继续与皮肤互斥，因此 0.1.6 直接复用 schema 10 的 `currentSkin`；
每个形态的换装选择仍写入既有 `companion.appearance.equipped` 分组，不新增持久化路径或迁移。若未来允许
形态与配色独立组合，才需要新字段、新 schema 和显式迁移。乌萨奇及其三件原有形态专属配饰均从 Lv.1
可选，其他款按上表等级解锁；形态的 Lv.1 可用性规则同时被皮肤命令、投影、换装命令与 schema 10 的 `currentSkin` 校验使用。旧账号无需
补写 `unlockedSkins`，切换形态仍只保存 `currentSkin`。

当前角色的可编辑 SVG、生成描述和编译方式见 PET_RIG。公开树不包含完整历史参考/母图与评审证据，不能把这些非运行来源视为开发或打包前提。素材范围见各 USAGE 与根目录 LICENSE-SCOPE；文档不确认第三方授权。

## 7. 开发检验台与热重载

开发档位 `npm run dev` 下，托盘右键菜单出现“宠物开发检验台”。检验台从 companion capability 的
`PET_CATALOG` 读取冻结目录，一次列出 32 个表情、43 个行为、12 个会话动作、42 个语义道具、25 个场景、
11 个皮肤/形态、41 个配饰和 4 个朝向；数量来自同一目录，不在预览层维护第二份列表。每个条目可单独触发，动作/会话/道具条目从点击时刻的第 0 帧开始播放。

托盘入口先同步开发标记再打开检验台，打开时收起命令菜单与喂食面板并暂停自主 cue。检验台的预览只存在于
renderer 的 `devPreview`：不写 canonical state、不增加装备字段、不增加 IPC command。开发窗口同时暴露
朝向、皮肤和等级选择，因此可以直接验证“Lv.20 + back + 小披风”这类组合；生产档位不生成菜单。

热重载只监听 `src`，过滤内容、core、pet surface 和 renderer 文件并做短 debounce；变化后只 reload
宠物窗口，reload 完成后主进程重新发送 `pet:sync`，检验台不会因为刷新丢失上下文。

## 8. 网格、实时计算与 SVG 的边界

历史 `0/1/2/3` 网格只约束旧像素资产，不是当前素材的强制格式。动作与扩展内容仍使用独立语义层：
`anatomy`（肩/肘/手掌）、`pose`、`view`、`anchor`、`layer`、`parts`、`z` 和 `bleed`。

当前混合渲染的边界是：

1. 团子兽直接复用生成 PNG 分层；乌沙奇 canonical 身体、脸与骨骼使用 SVG 编译路径，生成衣柜叠在同一美术空间
2. 身体缓存只随物理层、版本、实际视图、必要加载状态和隐藏部件变化；时间、表情和无关加载完成不能扩大身体缓存
3. 呼吸、眨眼、注视、拖拽倾斜、骨骼和粒子由纯采样及 Canvas 合成；剪影显著改变时用专门姿态素材，不能无限扭曲单张图
4. `rig/schema.mjs` 仍只收路径；PNG 走独立 `raster/schema.mjs`、加载和绘制适配器，不把 `<image>` 塞进路径 Rig
5. 肖像的身体/脸/衣物共用实际穿搭 fit bounds，ready 在 artwork 顶层透传并驱动冷启动重绘；静态预览不能等待用户再次操作才更新

## 9. 外部参考与采用边界

- Spine 官方 Skins 文档（`https://esotericsoftware.com/spine-skins`）：slot 通过 skin placeholder 切换附件，
  同一套动画驱动不同附件。借鉴的是“动作与装饰分开、共用锚点”的组织方式，不引入其 runtime 或素材。
- Godot 官方 Using AnimationTree（`https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html`）：
  离散动画切换与状态机路径。据此为前视/斜视/侧视提供离散原创形态再复用动作与附件，而不是把正面 sprite 无限压扁。

以上是设计参考，不是已落地功能，也不构成更换引擎的结论。当前 Electron/Canvas、纯投影和固定绘制顺序保持不变。

## 生图素材优先的当前生产流程

1. **固定唯一形象基准。** 保存用户本次指定原图、文件身份与 SHA-256；高分辨率同源图只能辅助细节，不能换成另一个新设计。
   现有素材身份以保存的 manifest、原始描述和编译输入为准；不以新生成的参考替换生产角色。
2. **先确认可用多视图。** 先生成透明的正面、左右双眼斜面和背面；不生成被用户否定的单眼完整侧面。
   同组素材固定体积、五官比例、配色、细节密度与阶梯轮廓节奏。素材格内不放标签、网格、地面或投影。
   检查实际 alpha、白色高光、同尺寸画布和脚底基线，按正常尺寸与放大图对照。未来角色的形象确认默认由用户完成，
   用户明确委托视觉决定时可由受托判断满足此关卡；获准夜间继续工作不等于每件素材已获用户逐项视觉认可。
3. **再锁关键动作定妆。** 用已确认多视图生成站立、跑步、回头、搬运与喝茶的关键姿态，先解决剪影、握点和遮挡关系，
   不靠扭曲单张正面图伪造任意角度。各动作可声明更窄的允许朝向。
4. **配饰单品与试穿一起验收。** 每件配饰输出透明单品、对应视角试穿与挂点信息；记录槽位、前后层、遮挡和互斥关系。
   没有试穿证据的漂亮单品不算完成，手持物还需共用手与工具接触点。
5. **固定场景母版后生成连续关键帧。** 固定镜头、角色比例、地面、背景与道具初始位置，明确准备、接触、发力、收回的顺序。
   逐帧检查身份、体积、脚数、接触和道具是否漂移；发现漂移时先修素材，不先加补间掩盖。
6. **再选择后加工与运行方式。** 小幅动作可用 PNG 分层和骨骼补间；明显换剪影、转身或遮挡变化需要专门姿态或序列帧。
   去背景仅处理外部连通背景，保留眼睛白色高光；不透明像素角色与茶汽、光晕等半透明效果不能共用二值 alpha 清理规则。
   缺失的隐藏区域必须补齐，关节保留实测重叠量。
   原始生图、清理后素材、处理参数和脚本分别保留，不用处理结果覆盖来源。
7. **按证据范围验收。** 先看实际生产绘制与连续接触，再看确定性、低刺激、内存、缓存、边界与多 DPI。
   数值检查不能替代“像不像”“是否自然”的用户判断；工具存在不代表所有素材已验收。

现有 `rig/schema.mjs` 与 `rig/paint.mjs` 继续只接受路径形状；PNG 走独立 `raster/` 适配器，复用
`rig/pose.mjs` 的纯矩阵。适配器明确资源 URL/版本、加载状态、alpha、缓存预算、层级、调色与清理所有权。
当前默认分派已接入团子兽生成素材，状态、IPC、装备规则和原生窗口几何不因美术替换而改变。

### 当前运行时与验收边界

团子兽的 `layeredReady` 表示核心分层可绘制，完整 `ready` 还要求当前表情、动作工具、衣柜和点缀可用；
冷加载时可先画同源 neutral PNG。乌沙奇生成衣柜全部 ready 后才隐藏被鞋替代的原腿，经典路径款始终沿原画笔。
`ready()` 等待完成不能掩盖失败；同时检查 pending、missing/failed、缓存统计与实际输出。
衣柜 readiness 必须放在 artwork 顶层，使 hero、形态缩略图、换装预览的订阅能在加载后重绘并在销毁时清理。

运行 PNG、运行时描述与编译 manifest 必须包含在公开源码和应用包中；编译检查验证现有输入的一致性，不等于能从母图重新生成全部美术。完整历史母图、参考与评审证据未全部随公开树交付。应用包仍排除 sources；资源过滤回归见 ARCHITECTURE「换装与伙伴形态」。

离屏 Skia 执行生产 painter、静态截图及数据测试，不能替代真实 Electron/浏览器桌面的透明窗口、GPU、缩放与交互验证。
团子兽循环切换皮肤的约 694 MiB 进程内存风险仍未关闭；对照表明原生 Skia 有贡献，但尚不能据此解释全部增长，
也不能用 JavaScript 缓存有上限或衣柜解码字节较小声称整体内存已解决。最新检查状态、限制和待办见 VALIDATION。

### 穿搭遮挡与肢体一体轮廓

一体感指最终可见轮廓连续，不禁止分层 rig。团子兽跑步使用生成的短脚突起，脚根深入身体；
原始栅格轮廓内的旧腹线由真实肢体填色遮住，仅裁切内部接合区，暴露的外轮廓仍保留。
近爪缩回身体边缘后方，不能用一个封闭圆爪贴在脸旁。透明连通、变动帧数都不能替代正常尺寸对闭合接缝的审视。

## 动画表达方式与片段契约

### 表达方式与接入边界

- 眨眼、呼吸、视线、小幅交互沿现有 Rig/程序动画；强转身、压缩、复杂接触采用逐姿态作品，不能用贴片数量证明质量。
- 不引入 Rive、Spine、PixiJS 或其他新渲染运行时，不采购或试用；不重建调度器、不把长会话烘焙成巨大序列。
- 只有现有 Rig 与姿态序列在同一冻结题目均因连续形变失败，才能重新评估加权网格及许可；不能自动启用。
- 团子兽保持已确认原图的纹理、软轮廓与身份；乌沙奇保留 canonical Rig 和双波浪嘴。新素材标准另需视觉确认。
- emotion-ball 只作概念参考，零代码零资产；来源范围未确认不能扩大。乌沙奇素材的个人本地使用限制继续有效。
- `form-art.mjs` 公开导出与 `ARTIST_METHODS` 不改；片段是角色画笔内部子模块，不是第二套 ClipAdapter 分派。
- 接入时用闭合 actionId 表声明接管；仅既有 `body` / `action` 调片段，未列动作保留原路径。
- `resolveArtwork` / `prepareArtwork` 承载完整组 readiness；加载中保留原画笔，失败显式报告，不能把失败当 ready。
- bounds 供 `spriteBounds`、肖像与命中共同消费；dispose/订阅并入原生命周期，不建另一套资源所有权。
- 坚持一个外部时间源、一个空间契约、一个服饰解析入口、一个 readiness 和一个提交后副作用边界。
- 不改 schema、装备三态、IPC、`main.js`、冻结中的 pet controller/renderer 或 popover 入口。

### 片段内容与纯采样

- 只读内容最终放 `src/content/companion/clips/<characterId>/<clipId>.json` 或 `.mjs`；不是用户持久化状态。
- `presentation/clips/clip-manifest.mjs` 是闭合 schema：未知字段、版本不支持、资源组缺项、哈希不符均失败关闭。
- `clip-sampler.mjs` 只消费注入的 action/view/outfit、进度与资源证据；不读时钟、随机数、DOM、文件或网络。
- `readyBundle` 绑定 characterId、clipId、contentVersion、resourceGroup 与完整 assetIds；旧角色/片段/版本/穿搭的 ready 不可复用。
- 输出局部帧、挂点、遮挡顺序、接触状态与 bounds；根位移单独交还呈现层，不能对身体、脸、衣物重复施加。
- 低刺激或 Reduce Motion 立即选 `staticPose`，不继续循环或根位移；动作切换和中断另有明确过渡验收。
- 默认 `faceMode=overlay`，眼嘴、眨眼与视线仍独立；`baked` 只允许逐项说明的脸部形变例外。
- 每帧必须交付独立 `bodyRecolorMask`，保护烤入衣物；不能用全图颜色阈值代替身体材质范围。
- 兼容表必须逐 action × view × outfit 声明 `supported/adapted/baked/unsupported`，缺行失败关闭，不偷偷丢衣服。
- `adapted/baked` 需明确适配或烤入的资源与理由；分别验证独立左右鞋、覆盖身体衣物与裸身。
- 四视图已有素材与 live 检查不等于所有大动作已兼容；现有正面 fit UI 的覆盖与侧背 fit 层序限制单独记录。
- 保留 `mirror-music`、`mirror-coding`、`mirror-ai` 和道具 `ai-chat` 的语义 ID；不得为片段改名。
- 内容测试须有合法样例、逐必填字段缺失、篡改哈希、相位回环、静态与兼容失败案例；验证通过不代表作品自然。
- 若另行提供母图，不将它们打入应用包；最终活动帧与清单必须进包，并扩展真实打包匹配器测试。

## 当前动作约束与推广门禁

Dango 跑步保留原 Rig 的双脚前后运动、身体呼吸伸缩及最小足部垂直回收相位；24 姿态跑步片段默认关闭，不作为生产默认。待机、专注、睡眠与显式醒来使用各自表达，连续状态过渡不得短暂露出其他状态。
手部轮廓跟随实际混合腕位，缩回后恢复短掌；服饰先完成完整潜在衣料再处理遮挡，不能用肤色补丁擦衣服。电脑屏幕朝伙伴，抚摸表达愉悦，不用调试动作代替真实输入语义。Usagi 的手根、鞋口、帽饰与嘴形要求见 PET_RIG。

内存与原生验收保持独立门禁：生产画笔、透明窗口、冷/热加载、换肤/穿搭、销毁后缓存释放及各进程增长需分别测量。已有长换肤离屏内存风险未关闭，不能仅凭 JS 缓存预算或短测宣称修复；原生实验未完成也不得写成通过。
大幅剪影实验只在单动作、默认关闭的角色内部实现；共用时间源、空间、服饰解析、readiness 和生命周期。新功能启用前验证原子 ready、静止位姿、循环连续、脚底接触、真实帧间隔及长时内存，再进行正常尺寸/速度的视觉审阅。当前 PET12 限制与所有原生验证范围以 VALIDATION 为准。
