# Gait playback review

Verdict: useful source-anatomy and timing candidate; do not enable in production. The fixed-world-ground contact contract works in this offline replay, but smooth silhouette transitions and host/outfit integration remain unaccepted.

## Evidence

- `old-new-same-scale-1x.png` and `old-new-same-scale-2x.png`: approved shallow quarter standing feet versus new near/far support feet, identical unchanged canonical body, common sole floor, identical hip x, light/dark, 99/198 CSS pixel body-design widths. No normalization to matching foot width or height. The original front foot is 19×9 alpha pixels; the actual quarter comparator is 18×9. New near/far support bounds are 21×12 and 20×12. The new exposed support profile is visibly fuller and more squared at the base; this is not hidden by shrinking it.
- `walk-replay-light-dark-1x-2x.gif`, `run-replay-light-dark-1x-2x.gif`, and matching MP4 files: actual helper outputs, 120 frames / two cycles each. GIF encoding uses 30 ms frame durations after GIF timing quantization (3.6 seconds total); the arbitrary preview tempo is not a product gait-speed decision. The movies keep a stationary world ground and camera while the canonical body travels; stance feet remain fixed in world coordinates. Body translation is rounded to art pixels. The GIF resets the two-cycle travel at its loop boundary; that scene reset is not a demonstrated seamless world-motion wrap.
- `walk-filmstrip.png`, `run-filmstrip.png`: exact frames from those replays at normal 99 CSS pixel body-design width, both backgrounds.
- `*-sample-light-dark-1x-2x.png`, `*-switch-detail.png`: normal/2× sample and frame-change close comparison.
- `source-mask-overlay.png`: actual v3 source with extraction polygons, without new painting.
- `samples.json`, `replay-audit.json`, `sample.mjs`, `render.py`, `audit.py`: reproducible timing, rendering and measurements. GIFs were decoded to verify 120 frames. Visual inspection was of decoded stills/filmstrips, not an interactive native-desktop playback observation.

## Findings

1. Support transfer: walk contains one and two support feet, with no flight; run contains zero and one support feet, with 27 sampled frames where both raster sole markers are above the fixed floor. Neither mode penetrates the floor. Measured stance-marker world drift is zero. This does not claim a flat full-width contact patch: each sole anchor is a lowest opaque pixel and the source sole is stepped.
2. Root depth: every foot overlaps canonical body alpha throughout the replay (minimum 81 foot pixels for walk, 76 for run). No fully detached foot occurs. This alpha overlap is a connectivity check, not anatomical or seam acceptance. Stance is behind the body; swing uses the previously proposed proximal-back/distal-front split. Lifted near-foot upper-edge shading/ink remains visible, and appearance can change at the support/swing depth transition. No body pixels, ear/face layers, or source foot pixels were repainted.
3. Silhouette switching: the continuous root removes large ankle jumps, but does not create in-between anatomy. At run q≈0.4167 the far reach→support change alters 221 root-aligned RGBA pixels with zero root displacement; near reach→support changes 215. These counts include shading as well as alpha. The filmstrip shows the tall/oblique shape snapping back to the shallow support shape. Four anatomical samples per side are not yet smooth animation acceptance.
4. Mask/body-contour interpretation: the source polygons include a small proximal strip of continuous pink torso tissue above the visible foot outlet. It is attachment overlap, normally hidden behind the body in support. The near support starts at source y417 while the belly/outlet lies lower, so raw alpha height alone overstates exposed foot height. The overlay does not establish an erroneous detached body-outline fragment that can safely be removed. The fuller visible sides/sole are genuinely in the source; merely deleting the hidden proximal strip would not restore the original shallow shape. No additional mask correction was made. It would be misleading to shrink the foot or trim genuine contour to force 19×9.
5. Body action: the canonical body remains unchanged and has no new bob, lean or ballistic vertical trajectory. Run has mathematical/raster foot flight but reads as low-amplitude gliding/stepping with a steady torso. This is insufficient evidence for a finished running action. Hands remain the approved resting hands, not a generated arm-swing cycle.

## Explicit limits

Only the right-facing two-eye quarter view and naked canonical body are covered. There are no front/back/side or mirrored gait approvals, source-compatible shoe bindings, heavy outfit tests, cached artist tests, DOM/CSS screenshots, cold/failure/reduced-motion paths, DPR/native-window acceptance, or actual host ground mapping. CSS dimensions here are deliberately rendered offscreen proxies, not browser evidence. No production files, feature flags, runtime adapter, wardrobe, persistence, or ground geometry were changed. Production stays disabled. No generation, push or publication was performed by this verification task.
