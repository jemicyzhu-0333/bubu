# 接触契约候选数据

文件：`contact-contract-candidate.json`。状态为 audit-only / productionReady=false；无生产改动、无持久化写入、无新增 IK 体系。引用采用逻辑素材名、相对仓库路径与 SHA256，不包含执行环境绝对路径。

## 已闭合的数据范围

- **hiccup / sip-tea**：双手持续握杯，真实 left/right 道具锚点分别登记。hiccup 保留最终(-1,-5)杯子修正；普通 sip 分持杯静止、提杯、入口高度停留、放下、持杯回静止五阶段。特殊纸机交接收杯仅作为该实例覆盖，不能改变普通 sip。
- **keyboard**：两手按既有 tap 正负半周期交替抬手与低位点触候选。JSON 记录现有轨迹公式、真实键盘锚点及旧 endpoint=掌心引导点的语义。低位点触仍 blocked：尚未证明旧掌心到新掌底的接触换算，也不把整个低位半周期冒充已证实的按键过程。
- **catch-star**：右手分接近自由手势与捕获后握持候选；左手明确 free，无 propAnchor、surface 或杜撰法线。其相对星星目标(-1.5,17)及星星仅有 right 锚点一并保留。
- **workout**：固定支撑面单列。新水平支撑来源法线可记录(0,1)，但加载/恢复时段和完整动作接触仍 blocked。明确 opaque center=floor−.5，不能用普通1.25误差门槛接受穿地。

杯子/键盘尚未验证的法线为 null + blocked，并写明缺失原因；不是根据动作名称猜一个方向。

## 验收指标分开

1. **静态持续握持**：逐手实际锚点、来源法线/柄轴、遮挡、自然开放腕根接合。静态关键姿态通过不代表动态已通过。
2. **动态持续握持**：上述约束覆盖整个持物区间；过渡、透明度和共同根变换连续。
3. **点触**：只在已证实的接触阶段检查掌底与键面的间隙/穿入；抬起阶段检查离面、方向和左右交替，不能强迫全程贴键盘。
4. **自由手势**：身份比例、五官避让、来源腕轴与连续轮廓，不要求道具接触误差。
5. **固定支撑**：检查真实不透明边界、零穿透、支撑漂移、加载/恢复阶段；marker 重合不能替代表面接触。

1707旧记录必须按真实实例、实际视图、手侧、role、phase及来源完备程度分组，禁止统一通过率冒充动作验收。

## 来源关键姿态可替代通用 IK

数据明确允许 source-contact-frames 作为同等候选实现，genericIKRequired=false。可在限定动作/手/阶段内用来源关键姿态与配套接触帧替代通用 IK；仍须提供来源哈希、同比例注册、真实接触/腕根、法线或柄轴、层序、自然开放接合及过渡覆盖。不能烘焙替换身体、挪道具、全局闭合掌根，或只凭静态帧宣称全循环通过。
